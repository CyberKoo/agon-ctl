# Windows 后端

## 1. 文档范围

本文说明 Windows 后端的显示器发现、身份合并、通道路由和厂商 SDK 适配。通用协议见《DDC 协议与功能》，模块依赖见《架构与接口》。

## 2. 支持的通道

| 提供方 | 运行库 | 标准 VCP | E2A0/F8E1 | 主要用途 |
|---|---|---|---|---|
| dxva2 | Windows 系统组件 | 支持 | 无 | 标准功能的默认通道 |
| Intel IGCL | `ControlLib.dll` 或 `ControlLib32.dll` | 支持原始 I²C 访问 | 支持 | Intel 原始通道和 EDID |
| AMD ADL | `atiadlxx.dll` 或 `atiadlxy.dll` | 支持原始 I²C 访问 | 支持 | AMD 原始通道和 EDID |
| NVIDIA NvAPI | `nvapi64.dll` 或 `nvapi.dll` | 支持原始 I²C 访问 | 支持 | NVIDIA 原始通道和 EDID |

厂商运行库仅从系统目录加载。各提供方独立加载和枚举。

Windows 实现范围限于 dxva2 和三家厂商 SDK，MDDCDRV、PCI 寄存器直接访问及内核驱动安装均在该范围之外。

## 3. 模块职责

| 模块 | 职责 |
|---|---|
| `discovery.rs` | 调用各提供方、保留部分成功结果、合并同一显示器 |
| `display.rs` | 保存显示器信息和通道，提供统一传输接口 |
| `routing.rs` | 选择通道、记录成功路由、准备读取恢复 |
| `identity.rs` | 判断跨提供方记录是否属于同一显示器 |
| `dxva2/mod.rs` | 物理显示器句柄生命周期、句柄刷新和身份匹配 |
| `dxva2/discovery.rs` | 枚举物理显示器、获取设备路径和生成临时 ID |
| `dxva2/transport.rs` | 标准 VCP 的 `PacketTransport` 实现和传输错误识别 |
| `dxva2/registry_edid.rs` | 通过 SetupAPI 和注册表读取、校验 EDID |
| `sdk/` | 厂商运行库初始化、显示器枚举、EDID 读取和原始包传输 |
| `library.rs` | 动态库生命周期和函数符号解析 |

SDK 类型和动态库加载器仅供 crate 内部使用。调用方使用 `WindowsDisplay`、`WindowsError` 和枚举函数。

## 4. 显示器发现

枚举按以下顺序执行：

1. 枚举 dxva2 物理显示器。
2. 分别尝试 IGCL、ADL 和 NvAPI。
3. 保存成功记录以及可用的 EDID 基本块。
4. 根据身份规则合并属于同一显示器的通道。
5. 返回合并后的 `WindowsDisplay` 列表。

局部失败通过诊断回调报告。存在可用结果时返回部分成功列表；结果为空时返回首个枚举错误。

厂商枚举同样保留部分结果。某个适配器、输出或 EDID 读取失败时，继续处理其他输出。

## 5. 显示器身份

### 5.1 dxva2 身份来源

dxva2 优先使用显示器设备接口路径。取得路径的过程包括：

1. 从 `HMONITOR` 获取 GDI 设备名称。
2. 枚举该设备下的显示器接口。
3. 仅在物理显示器和接口均为一一对应时采用该路径。
4. 通过 SetupAPI 找到设备节点，并读取设备参数中的 EDID。

接口路径按不透明标识处理，设备实例由系统接口映射确定。路径比较前统一 ASCII 大小写。

无法形成可靠的一对一映射时，EDID 保持为空，并生成带 `dxva2:fallback:process-…:token-…` 前缀的临时 ID。临时 ID 仅限当前进程内的精确选择。

### 5.2 跨提供方合并

强身份由厂商 ID、型号 ID 和有效序列号组成。序列号为 0 或 `u32::MAX` 时改用完整的 128 字节 EDID 基本块进行比较。

合并必须同时满足：

- 身份证据一致。
- 每个提供方在合并组中最多出现一次。
- 组内所有记录两两一致。

相同 EDID 或相同序列号可能出现在多台同型号显示器上，因此存在歧义的记录保持独立。合并规划基于全部原始记录，统一计算分组后再执行合并。

## 6. 通道路由

### 6.1 合格通道

标准地址可以选用 dxva2 或原始通道，扩展地址使用原始通道。能力串 `F3` 查询从标准通道开始，dxva2 拒绝该请求时按普通读取恢复流程切换到原始通道，每次传输完整的请求和响应片段。标准地址和扩展地址分别记录最近一次成功的路由。

初始选择遵循以下规则：

- 标准地址存在 dxva2 时优先使用 dxva2。
- dxva2 通道缺失时选择第一个原始通道。
- 原始通道缺失时，扩展地址返回 `UnsupportedFeature` 并结束操作。

### 6.2 读取恢复

一次读取及其响应始终在同一通道完成。读取失败后，路由可以在合格通道组成的环中选择下一个候选，核心读取客户端将总尝试次数限制为三次。

以下情况结束当前读取：

- 显示器通过结果码明确拒绝地址。
- 请求本身无效。

通道能力缺失时选择另一个合格通道。单通道的暂时性故障按总预算重试。

当 dxva2 返回 `ERROR_GRAPHICS_MONITOR_NO_LONGER_EXISTS`（`0xC026258D`）时，当前读取尝试结束后重新枚举物理显示器。设备接口路径可用时按路径匹配，否则仅接受唯一的物理描述匹配；仅在匹配唯一时替换句柄，其余情况保持当前状态。成功替换句柄后，下一次尝试仍使用 dxva2，恢复失败才按普通读取故障切换通道。重枚举沿用三次读取的总尝试预算，且仅执行读取恢复操作。

成功路由用于后续读写，其余候选仅参与本次恢复。

### 6.3 写入约束

写入使用已有成功路由或默认合格路由。每次写入操作只发送一次，失败后保留原通道并报告结果。写入完成后由核心 OSD 层回读结果。

## 7. 厂商适配

### 7.1 dxva2

dxva2 处理标准 VCP 正文：

- 读取正文 `01 VCP` 暂存 VCP 码，实际系统调用在读取响应时执行。
- 写入正文 `03 VCP vH vL` 转换为 `SetVCPFeature`。
- 其他地址返回通道支持缺失。

读取结果转换为通用的 11 字节响应，再由核心协议解析。物理显示器句柄由 `Dxva2Display` 负责释放。

### 7.2 Intel IGCL

IGCL 适配保存 API 句柄以及枚举、面板描述符和 I²C 函数指针。显示器对象通过引用计数保持提供方和运行库存活。

I²C 请求遵守以下参数：

| 操作 | `address` | `operation_type` | `offset` |
|---|---:|---:|---:|
| 写入 DDC/CI 请求 | `0x6E` | 写入 | `0x51` |
| 读取 DDC/CI 响应 | `0x6E` | 读取 | `0` |

写请求去掉通用报文首字节后填入 IGCL 数据区。读响应保留完整的 DDC/CI 帧。单个请求的数据长度上限为 `CTL_I2C_MAX_DATA_SIZE`。

EDID 先读取基本块，再根据扩展块数量尝试读取第一个扩展块。扩展块缺失、截断或读取失败时保留有效基本块。

### 7.3 AMD ADL

ADL 的 EDID 和 DDC 调用固定使用逻辑显示器索引。显示器对象保持 ADL 上下文和运行库存活，上下文在最后一个引用释放时销毁。

写请求在通用报文前添加 `0x6E` 后调用 `ADL2_Display_DDCBlockAccess_Get`。读请求使用 `0x6F`，并检查实际返回长度。ADL 分配的显示器数组必须由与分配回调相同的 C 运行库释放函数释放。

EDID 长度必须在 128 至 256 字节之间，基本块必须通过核心 EDID 校验。

### 7.4 NVIDIA NvAPI

NvAPI 通过 `nvapi_QueryInterface` 取得函数地址。当前使用的接口包括：

| 接口 | 接口 ID |
|---|---:|
| `NvAPI_Initialize` | `0x150E828` |
| `NvAPI_EnumPhysicalGPUs` | `0xE5AC921F` |
| `NvAPI_GPU_GetConnectedDisplayIds` | `0x078DBA2` |
| `NvAPI_GPU_GetEDID` | `0x37D32E69` |
| `NvAPI_SYS_GetGpuAndOutputIdFromDisplayId` | `0x112BA1A5` |
| `NvAPI_I2CWrite` | `0xE812EB07` |
| `NvAPI_I2CRead` | `0x2FDE12C5` |

枚举得到的显示 ID 必须转换为 GPU 句柄和输出位掩码。GPU 句柄必须指向有效对象，输出值必须是非零的 2 的幂；任一条件失败时，该记录无效。

I²C 请求使用 `NvI2cInfoV3`，版本字段为 `0x30000 + size_of::<NvI2cInfoV3>()`。写入使用设备地址 `0x6E`，读取使用 `0x6F`，输出位掩码来自转换结果。返回的数据长度超过调用方缓冲区时按错误处理。

## 8. 错误与资源管理

动态库加载失败、符号缺失、系统调用失败和无效数据使用 `WindowsError` 表示。原始通道操作使用核心 `TransportError`，由核心层转换为 DDC 或 OSD 错误。

各提供方对象负责自身资源：

- 动态库在最后一个引用释放时卸载。
- IGCL API 句柄和 ADL 上下文随提供方销毁。
- dxva2 物理显示器句柄随显示器对象销毁。
- SetupAPI 设备信息集合和注册表键由局部所有者释放。

这些对象的生命周期由专用工作线程管理。FFI 会话在同一线程中创建、使用和销毁它们。
