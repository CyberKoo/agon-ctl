# 架构与接口

## 1. 文档范围

本文说明工作区的职责划分、依赖关系、传输接口、平台适配方式以及对外提供的命令行和 C 接口。协议细节见《DDC 协议与功能》，测试方法见《测试与验收》。

## 2. 工作区结构

核心协议位于依赖关系的底层，平台实现依赖核心协议，命令行程序和 C 接口位于调用方一侧。原始系统绑定仅处理平台 ABI。

| 模块 | 职责 |
|---|---|
| `agon-osd` | 地址模型、DDC/CI 报文、功能定义、EDID 解析、OSD 读写和错误类型 |
| `agon-osd-linux-sys` | Linux `i2c-dev` 所需的常量和 `ioctl` 声明 |
| `agon-osd-linux` | Linux 显示器枚举、设备打开和原始包传输 |
| `agon-osd-macos-sys` | CoreFoundation、CoreGraphics、CoreDisplay 和 IOKit 的原始声明 |
| `agon-osd-macos` | macOS 对象生命周期封装、显示器枚举和原始包传输 |
| `agon-osd-windows-sys` | IGCL、ADL 和 NvAPI 的 ABI 类型、常量及函数指针类型 |
| `agon-osd-windows` | Windows 显示器发现、身份合并、通道路由和 SDK 传输 |
| `agon-osd-ffi` | 静态 C ABI、会话工作线程、快照和错误对象 |
| `agon-ctl` | 命令解析、显示器选择、操作调度和结果输出 |

各 crate 的公开入口保持精简。Windows 的 SDK 加载器、原始通道和发现结果类型仅供 crate 内部使用。

## 3. 核心协议与传输接口

### 3.1 两层传输接口

`PacketTransport` 表示单一物理通道上的原始字节读写：

```rust
fn write_packet(&mut self, packet: &[u8]) -> Result<(), TransportError>;
fn read_packet(&mut self, response: &mut [u8]) -> Result<(), TransportError>;
```

`DdcTransport` 以地址、值或能力片段表达操作：

```rust
fn read_vcp(&mut self, address: Address) -> Result<VcpValue, DdcError>;
fn write_vcp(&mut self, address: Address, value: u16) -> Result<(), DdcError>;
fn read_capabilities(&mut self, offset: u16) -> Result<CapabilityFragment, DdcError>;
fn recover_read(&mut self, address: Address, error: &DdcError) -> bool;
fn recover_capabilities(&mut self, error: &DdcError) -> bool;
```

`DdcRequest::{Vcp, Capabilities}` 在重试和多通道路由中分别承载普通 VCP 读取与能力串请求。`CapabilityFragment` 归属协议层，传输层单向调用协议层。通道能力受限时返回独立的 `UnsupportedCapabilities` 错误。

核心库为所有实现 `PacketTransport` 的类型自动提供 `DdcTransport` 实现。平台叶节点处理系统调用和字节传输。多通道类型直接实现 `DdcTransport`，并直接接收地址、值或能力片段。缺少能力串通道的实现沿用默认的 `read_capabilities`，返回 `UnsupportedCapabilities`。

### 3.2 读写协调

`DdcClient` 负责读取重试和命令间隔。单个读取操作最多尝试三次，`recover_read` 负责准备下一次尝试，具体工作限于更新通道选择。

`Osd<T>` 负责功能级读写：

- 读取返回当前值和最大值。
- `capability/cache` 负责拼接和解析能力串，并为每个 `Osd` 连接保存一份快照。`read_capabilities` 首次成功时建立快照，后续返回同一快照的借用。缓存仅保存成功解析的结果，读取或解析失败后，下次调用从偏移 0 重试。`read`、`set`、`probe` 沿用现有快照，重建 `Osd` 时快照自然失效。
- `DeviceCapabilities` 独立保存能力串和解析结果，按地址返回设备原始值列表，完整保留上报顺序和重复项，返回内容独立于本地枚举和 `maximum`。
- `Feature::support_path()` 集中维护逐码支持集判定策略：`SupportPath::CapabilityList` 表示使用能力串显式列表，`SupportPath::Maximum` 表示使用 `maximum` 规则，其余功能返回 `None`；CLI 共用核心策略分派。
- 写入前读取当前值，纯数值功能据此检查最大值。
- 命名功能接受完整 `u16` 数值，最大值检查仅用于纯数值功能。
- HDR 和 LightFXMode 的候选表及选择规则由核心功能元数据维护，读取显示与名称写入共用预读得到的 `maximum`；CLI 和 FFI 共用核心选表逻辑。
- 写入只发送一次，随后读取结果。
- 写入传输异常使用 `WriteUncertain`；写入完成后的回读失败使用 `ReadbackFailed`。两种情况均只发送一次写入。

## 4. 平台适配

### 4.1 Linux

Linux 后端读取 `/sys/class/drm`，选择已连接且具有 DDC 通道的外接连接器，再打开对应的 `/dev/i2c-N`。控制范围仅包括外接连接器，`eDP`、`LVDS` 和 `DSI` 内置连接器直接跳过。单个连接器或设备打开失败时跳过该记录，保留其他结果。

`I2cDevice` 独占设备文件，打开时通过 `I2C_SLAVE` 设置从机地址。原始读写分别使用 `write_all` 和 `read_exact`。详细说明见《Linux 后端》。

### 4.2 macOS

macOS 后端分为原始绑定、框架封装和显示器实现三层。CoreFoundation 对象由所有者类型负责释放，IOKit 注册表对象由封装类型负责释放。

显示器实现处理在线外接显示器，并按注册表遍历顺序将 `DCPAVServiceProxy` 关联到最近的帧缓冲节点，再通过 `IODisplayLocation` 选择唯一可用候选。存在多个可用候选时拒绝绑定。对象创建、使用和销毁均由专用工作线程执行。详细说明见《macOS 后端》。

### 4.3 Windows

Windows 后端按职责划分为以下模块：

| 模块 | 职责 |
|---|---|
| `display.rs` | `WindowsDisplay` 的对外行为和传输委托 |
| `discovery.rs` | 各提供方枚举、错误汇总和身份合并 |
| `identity.rs` | 接口路径规范化、EDID 与序列号身份判断 |
| `routing.rs` | 标准与扩展地址的通道选择、恢复和成功路由记忆 |
| `dxva2/` | 物理句柄生命周期、标准 VCP、显示器发现、dxva2 身份来源和注册表 EDID |
| `sdk/` | IGCL、ADL 和 NvAPI 的加载、枚举与原始通道 |
| `library.rs` | 系统目录中的动态库加载和符号解析 |
| `error.rs` | Windows 错误类型 |

具体行为见《Windows 后端》。

## 5. 枚举诊断

Linux 和 Windows 提供两种枚举方式：

- `enumerate()` 返回显示器列表并丢弃可恢复的诊断信息。
- `enumerate_with_diagnostics(callback)` 通过回调报告局部失败，由调用方决定处理方式。

命令行程序将诊断信息写为标准错误。FFI 使用静默枚举，错误通过状态码和错误对象返回。诊断信息的展示由调用方统一决定。

## 6. C 接口

### 6.1 构建产物

FFI crate 生成静态库，头文件为 `crates/agon-osd-ffi/include/agon_osd.h`，ABI 版本为 2。

```bash
cargo build -p agon-osd-ffi --profile ffi --locked
```

Linux 和 macOS 的产物为 `target/ffi/libagon_osd_ffi.a`，Windows MSVC 的产物为 `target/ffi/agon_osd_ffi.lib`。指定 `--target` 时，产物位于相应的目标目录。

`ffi` profile 将 panic 策略设置为 `unwind`，使库能够在 C ABI 边界前捕获 panic 并转换为错误状态。普通 `release` profile 使用 `abort`，FFI 构建固定选择 `ffi` profile。

### 6.2 会话与对象所有权

典型调用顺序如下：

1. `agon_session_create` 创建会话和专用工作线程。
2. `agon_session_refresh` 枚举显示器并返回独立快照。
3. `agon_display_list_get` 读取显示器信息和用于后续调用的 ID。
4. 使用 `agon_read`、`agon_set`、`agon_probe` 或 `agon_feature_capabilities` 执行操作。
5. 使用对应的销毁函数释放列表、错误对象和会话。

显示器列表拥有自己的字符串，快照生命周期独立于后续刷新和会话销毁。错误对象拥有独立消息。静态功能元数据字符串由库持有。

所有功能的命名值统一通过 `agon_feature_named_values` 获取：调用方把 `agon_read` 或 `agon_probe` 返回的 `maximum` 传给核心选表逻辑，得到独立的 `agon_named_value_list_t`，再通过 `agon_named_value_list_count/get` 读取候选项，最后用 `agon_named_value_list_destroy` 释放。静态功能可使用任意 `maximum`，纯数值功能返回空列表。列表拥有自己的名称字符串，创建列表只处理内存中的元数据。

`agon_feature_support_path` 以 `AGON_SUPPORT_PATH_*` 枚举导出核心支持策略，仅查询核心元数据。`agon_feature_capabilities` 在工作线程中复用对应 `Osd` 的能力快照，只有首次成功调用会读取设备能力串；成功的 `agon_session_refresh` 会重建连接并使旧快照失效。每次调用仍返回独立拥有的 `agon_capability_list_t`；调用方通过 `agon_capability_list_count/get` 读取原始 `uint8_t` 列表，并用 `agon_capability_list_destroy` 释放。该列表完整保留设备原始顺序和内容，独立于本地枚举和 `maximum`，生命周期独立于后续调用和会话销毁。

FFI 的 `feature.rs` 统一负责功能元数据、支持策略和命名值导出，`capability.rs` 只负责能力列表对象及其 C ABI；共享的参数校验和错误转换保留在 crate 根部，设备访问仍由 `session.rs` 与 `backend.rs` 协调。

同一会话的调用可以来自多个线程，硬件操作在工作线程中串行执行。销毁会话前，调用方必须确保其他调用已经结束。非空指针须有效、可写并指向彼此独立的内存区域，具体要求以头文件为准。

### 6.3 错误处理

返回 `AGON_OK` 表示成功。其余状态码分别表示参数错误、平台支持缺失、显示器选择失败、功能支持缺失、值超过上限、传输错误、响应无效、写入结果待确认、回读失败和内部错误。

非空 `out_error` 在成功时接收空指针，在失败时接收需要由 `agon_error_destroy` 释放的错误对象。重复使用输出位置前，调用方必须已经处理原有对象。

## 7. 命令行接口

`src/app.rs` 负责命令调度，`src/output.rs` 负责文本格式，`src/platform.rs` 负责选择平台实现和打印枚举诊断。

显示器选择规则如下：

- 单显示器场景可以省略 `--display`。
- 多显示器场景必须提供选择器。
- 选择器可以精确匹配显示器 ID，名称匹配则忽略 ASCII 大小写。
- 名称匹配到多台显示器时改用 ID。

命令行读取、设置和能力探测均复用核心 `Osd<T>`，协议与重试规则统一由核心库提供。
