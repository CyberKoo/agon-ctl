# 测试与验收

## 1. 文档范围

本文说明单元测试、静态检查、跨目标编译检查、C 链接检查和硬件验收方法。普通测试使用模拟实现和临时数据，硬件操作作为独立验收执行。

## 2. 本地检查命令

在仓库根目录执行：

```bash
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo +1.85.0 check --workspace --all-targets --locked
```

测试总数随实现调整，以命令输出为准。

按 crate 或测试名称筛选：

```bash
cargo test -p agon-osd --locked
cargo test -p agon-osd-windows --locked
cargo test -p agon-osd-linux --locked
cargo test -p agon-osd-ffi --locked

cargo test -p agon-osd-windows --locked \
  routing::tests::write_failure_never_falls_back_or_rewrites -- --exact
```

## 3. 跨目标编译检查

```bash
cargo check --workspace --all-targets --locked --target x86_64-pc-windows-gnu
cargo check --workspace --all-targets --locked --target i686-pc-windows-gnu
cargo check --workspace --all-targets --locked --target aarch64-apple-darwin
cargo check --workspace --all-targets --locked --target aarch64-unknown-linux-gnu
```

交叉编译检查仅验证目标代码能够编译。对应操作系统的原生测试另行执行。

## 4. 单元测试组织

### 4.1 核心协议和 OSD

地址编码、请求组帧、响应解析、EDID 和功能值解析直接构造输入并检查结果。

OSD 读写通过实现 `PacketTransport` 的模拟通道完成。模拟通道记录请求，并按预设顺序返回响应或错误。测试重点包括：

- 标准地址和扩展地址的报文内容。
- `F3` 能力请求的偏移编码、`E3` 响应校验以及短片段和空片段拼接。
- 同一连接的能力串只读取和解析一次；读取或解析失败后从偏移 0 重试，并丢弃已读取的部分数据，缓存仅保存成功结果。
- 标准码、扁平扩展码和命名空间括号形式的值列表解析；列表顺序和重复项保持不变。
- `capabilities` 列表的十进制格式化。
- 校验失败、无效响应和短传输。
- 读取最多尝试三次。
- 地址支持缺失时按约定停止或恢复。
- 写入异常时只发送一次。
- 回读失败时保持单次写入。
- 纯数值功能的最大值检查和命名功能的数值兼容性。

### 4.2 Windows 路由和身份

路由测试使用模拟标准通道和模拟原始通道，以事件序列记录每次读写。测试重点包括：

- 一次请求和响应留在同一通道。
- 标准地址与扩展地址分别记录成功路由。
- 多通道共享同一个读取尝试预算。
- 写入失败时保留原通道和单次写入语义。
- 合格通道缺失时跳过输入输出。

身份测试直接构造 `DisplayInfo` 和 EDID 基本块，覆盖有效序列号、缺失序列号、重复 EDID、重复提供方及两两冲突等情况。

IGCL、ADL 和 NvAPI 的模拟函数测试需要在 Windows 上运行，通过替换厂商函数指针完成。ADL 测试还覆盖断开输出及无效状态掩码的过滤、物理输出别名去重、失败别名不阻塞后续有效别名，以及相同 EDID 的不同物理输出保持独立。

### 4.3 Linux 枚举

Linux 测试在临时目录中建立连接器、`status` 文件和 `ddc` 符号链接。设备打开通过闭包替换，诊断消息通过回调收集。

测试重点包括：

- 内置连接器的排除。
- 连接器名称和总线编号解析。
- 断开、缺失文件、无效链接和权限错误。
- 单个设备失败时保留其他结果。
- 根目录读取失败时返回错误。
- 诊断数量和诊断内容。

### 4.4 FFI 会话和 C ABI

`Backend` 模拟实现用于验证会话行为。测试重点包括：

- 后端在工作线程中创建、调用和销毁。
- 初始化失败、操作 panic 和工作线程断开。
- 并发调用各自获得正确响应。
- 快照生命周期独立于刷新和会话销毁。
- 错误对象独立分配并正确释放。
- 空指针、无效 UTF-8、无效索引和未知功能。
- 按 `maximum` 返回命名值列表，覆盖静态、动态和纯数值功能，并验证独立字符串生命周期和无效输入。
- 支持策略枚举映射、设备原始能力列表、工作线程调度及列表在会话销毁后的独立生命周期。
- 多个显示器分别复用自身能力快照；刷新替换连接后，新连接重新读取能力并建立快照。
- 所有核心错误到 C 状态码的映射。

C ABI 测试使用原始指针时，必须遵守与 C 调用方相同的生命周期约定，并在测试结束前销毁返回对象。

### 4.5 系统绑定

`*-sys` crate 主要检查结构大小、对齐、字段偏移、常量和默认值。能在编译期完成的检查应使用常量断言。

## 5. C 静态链接检查

Linux 上执行：

```bash
cargo build -p agon-osd-ffi --profile ffi --locked

cc -std=c11 -Wall -Wextra -Werror \
  -Icrates/agon-osd-ffi/include \
  crates/agon-osd-ffi/examples/smoke.c \
  target/ffi/libagon_osd_ffi.a \
  -lpthread -ldl -lm \
  -o target/agon-osd-ffi-smoke

target/agon-osd-ffi-smoke
```

该程序检查 ABI 版本、功能元数据、无效参数、错误对象以及空会话生命周期。

其他平台的系统链接参数可以通过以下命令查询：

```bash
cargo rustc -p agon-osd-ffi --profile ffi --locked -- --print native-static-libs
```

## 6. 持续集成检查

CI 在 Linux、Windows 和 macOS 上分别执行格式检查、工作区测试和 Clippy，并在三种系统上检查 Rust 1.85 兼容性。另有 Windows x86、macOS ARM64 和 Linux ARM64 的跨目标编译检查。

提交前应至少在本地通过第 2 节命令。涉及平台代码时，还应执行相应的跨目标检查及该平台的原生测试。

## 7. 硬件验收

硬件验收先执行只读操作，确认设备选择和响应正常后，再使用亮度等低风险设置进行写入。每次写入都应记录原值、修改后回读、恢复原值并再次确认。重试行为通过模拟故障验证，写入验收使用低风险设置。

### 7.1 通用项目

- 单显示器省略选择器时能够正确操作。
- 多显示器可以按 ID 和名称分别选择，歧义选择在命令发送前返回错误。
- 标准 VCP、E2A0 和 F8E1 读取结果正确。
- 功能支持缺失时在命令发送前返回能力错误。
- 拔插设备或通道断开后，读取仍遵守三次尝试限制。

### 7.2 Windows

- AMD：逻辑索引与物理索引不同的输出能够正确读取和设置。
- Intel：单个输出异常时其他输出保持可用，扩展 EDID 块失败时保留基本块。
- NVIDIA：显示 ID 转换、EDID 获取及三组地址读取正确。
- dxva2：设备路径、注册表 EDID、镜像或多物理显示器场景使用独立且可验证的身份。
- 路由：标准通道失败后能够从原始通道重新发送完整查询，写入失败保留原通道并报告结果。
- 同型号且缺少序列号的多台显示器保持独立记录。

### 7.3 macOS

- 单台外接显示器的标准地址和扩展地址读取正常。
- 多台显示器可以分别选中并恢复低风险设置。
- 服务匹配失败时终止该显示器的操作。
- CoreFoundation 和 IOKit 对象在成功、失败和候选歧义时均能正确释放。

### 7.4 Linux

- 笔记本内置面板与外部显示器同时存在时，仅选择外部显示器。
- 权限不足、设备拔插和无效连接器出现时，其他设备继续枚举。
- 对 `/dev/i2c-N` 的读写使用预期从机地址和完整报文。

## 8. 验证边界

厂商驱动、固件和物理连接的兼容性通过硬件验收确认。动态库加载通过目标系统的原生测试确认。上述硬件验收需在相应平台和设备组合上分别完成。
